# Conventions

[CLAUDE.md](../CLAUDE.md) の補足詳細。

## テーマディレクトリの構成パターン

- `*.html` — 実装本体
- `docs/0N-xxx-plan.md` — デモごとの開発計画書。**計画書単体で実装を完遂できる詳細度**(アルゴリズム、パラメータ具体値、実装手順、完成判定チェックリスト)で書く。途中でレート制限にかかっても別モデルが引き継げるようにするため。
- `README.md` — デモ一覧表(手法・計画書へのリンク)と、実際に投げたプロンプト履歴を記録

## 3DCG モデル比較の構成

`3DCG/` はモデル比較そのものが目的のディレクトリ構成を取る。例: `mls-mpm-snow/{fable5,opus}/index.html` のように同一プロンプト(`PROMPT.md`)をモデルごとのサブディレクトリで独立実装させ、`RESULTS.md` に比較結果(スクリーンショット付き)をまとめる。

モデル比較を行う際:
- 各モデルの作業ディレクトリを分離し、プロンプトで作業範囲を該当ディレクトリ配下に限定、比較対象となる他モデルの実装ディレクトリを閲覧・参照させないよう指示する(`3DCG/mls-mpm-snow/PROMPT.md` 参照)。
- 数値シミュレーション系(流体・MPM 等)の評価では、起動直後のスクリーンショット一枚では安定性の破綻(発散・爆発)を見逃す。**最低 60 秒程度放置してから比較**すること(`3DCG/mls-mpm-snow/RESULTS.md` の教訓)。

## 生成物の扱い

`output/`(スクリーンショット等の検証時生成物)と `3DCG/mls-mpm-snow/results/` は gitignore 対象。

## 単一 HTML デモの規約

現行の `fluid-demos/`, `anime-effects/`, `3DCG/` のデモに適用される規約(ビルドを伴う新テーマにはそのまま適用されない)。

- **単一 HTML ファイル完結**。CSS/JS はインライン。外部ライブラリを使う場合も `<script type="importmap">` + CDN(jsdelivr 等)の ESM import に留め、ビルドステップやローカル `fetch`・モジュール分割は行わない(`file://` で動作させるため)。例外: `3DCG/city-flight-real/` は Three.js や 3d-tiles-renderer 等を importmap 経由の CDN から読み込む。
- ダークテーマ基調、日本語タイトル・`<html lang="ja">`。
- `requestAnimationFrame` ループを使うデモは、タブ復帰時の巨大な dt でシミュレーションが発散しないよう dt をクランプする。
- API キーが必要なデモ(例: `3DCG/city-flight-real/` の Google Maps API キー)は、ブラウザ側の入力欄経由でユーザーに直接入力させる方式を取り、リポジトリやコードにキーをハードコードしない。`.env` はローカルの秘密情報置き場であり、デモ本体からは読み込まれない。
