# 設計プラン 02: 自然音声優先方式(クラウド Neural TTS × 同一 Remotion バックエンド)

> **一行サマリー**: プラン01の疎結合設計を活かし、TTS だけをクラウド Neural 音声(Azure / ElevenLabs)に差し替える変種。声の自然さ・感情表現を最優先する回向け。同期は「合成前決定論」が使えないので **word-boundary イベント/強制アライメント**で `timeline.json` を作る。映像・合成・レビュー体系はプラン01と共通。

このプランは**プラン01の完全な代替ではなく、TTS モジュールだけを差し替えた姉妹プラン**である。工程①②④b以降(構造パース・シナリオ生成・映像合成・レビュー体系)はプラン01と同一なので、ここでは**差分だけ**を記す。

---

## 1. なぜ別プランか

VOICEVOX は同期に最適だが、感情の起伏・自然な間・「楽しく気楽に」の温度感では最新クラウド Neural 音声に一歩譲る。**声の魅力が視聴体験を左右する回**(例:感情に訴えるフック、しみじみ語る `お金で幸福は買えるか`)では、自然さを取りたい。プラン01のパイプラインは TTS を疎結合にしてあるので、この差し替えが低コストで可能。

トレードオフを明示: 自然さ↑ / 従量課金発生 / **発話尺が合成前に確定しない**(=同期方式を変える必要)/ ネットワーク・データ送信(健康テキストの外部送信可否は要確認)。

---

## 2. 差分①: TTS 選定

| 候補 | 長所 | 短所 | 同期に使う時刻情報 |
|---|---|---|---|
| **Azure AI Speech(日本語 Neural, 複数話者)** | 自然・安価・**word/viseme boundary イベントを合成と同時に返す**(同期に理想的)・SSMLで間や強調を細かく制御 | クラウド送信 | `WordBoundary`/`VisemeReceived` イベント(発話開始からのオフセット) |
| **ElevenLabs(v3, 多言語)** | 表現力・キャラ性が随一、掛け合いが活き活き | やや高価・日本語は英語比でやや癖・タイムスタンプ API は要確認 | `character/word timestamps` API、無ければ WhisperX で後付け |
| **Google Cloud TTS(日本語 Neural2/Studio)** | 安定・安価 | 単語タイムスタンプは限定的 | WhisperX/whisper.cpp `--dtw` で強制アライメント |

**推奨は Azure**。理由: 日本語 Neural の品質・コストのバランスが良く、**WordBoundary イベントが「合成と同時に」語ごとのオフセットを返す**ため、プラン01の決定論には劣るが後付け推定なしで `timeline.json` を作れる。ElevenLabs は「声の魅力を最大化したい看板回」の切り札として選択式に。

---

## 3. 差分②: 同期方式(合成前確定が使えない場合)

VOICEVOX の mora 長式は使えないので、**合成時/合成後に語タイムスタンプを取得**して同じ `timeline.json` 形式に流し込む。後段(Remotion)はプラン01と完全に同一で無改変。

**経路A(Azure, 推奨)**: 合成 API に SSML を渡し、返ってくる `WordBoundary` イベント列(各語の `AudioOffset`)をそのまま `wordTimings` に変換。発話尺=最後のイベント+末尾無音。**後付け書き起こし不要**。

```csharp
// 概念: 合成しながら語オフセットを収集
synthesizer.WordBoundary += (s, e) =>
    words.Add(new { text = e.Text, startSec = e.AudioOffset / 1e7 }); // 100ns単位→秒
```

**経路B(ElevenLabs/Google でタイムスタンプが弱い場合)**: 合成した WAV を **WhisperX または whisper.cpp `--dtw`** で強制アライメントし、語単位の開始/終了秒を得て `wordTimings` を構築。`--dtw` は DTW ベースで通常の Whisper より時刻精度が高い(RTX 4090 で高速・ローカル完結、テキスト外部送信も避けられる)。

**尺の揺れ対策**: 事前確定はできないが、(1)合成→実測尺を得てから 5分ガードを判定し、超過なら台本を自動圧縮して**再合成**、(2)話者交代の「間」は SSML の `<break>` かポスト処理で挿入し timeline に反映。プラン01の `pacing.json` をそのまま流用。

**話者交代・テンポ**: Azure は SSML `<prosody>`/`<break>` で話者ごとの速度・間をきめ細かく制御できる利点があり、掛け合いの生っぽさはむしろ01より出しやすい。

---

## 4. 差分③: コスト

| 項目 | 概算 |
|---|---|
| Azure Neural TTS | 台本 ~1800字×2話者 ≈ 3600字/本 → **$4/百万字換算で 1本 ¥数円〜十数円**(実質微少) |
| ElevenLabs | 文字あたり高め。看板回のみ使用で月数百円〜規模次第 |
| WhisperX/whisper.cpp | ローカル¥0(4090 or Mac) |
| 初期構築の差分 | TTS モジュール差し替え **+0.5〜1人日**(プラン01が土台にある前提) |

金銭コストは依然小さいが、**VOICEVOX の完全¥0・完全ローカルに対しては「従量課金+外部送信」が発生**する点がトレードオフ。

---

## 5. リスクの差分

| リスク | 対策 |
|---|---|
| 健康テキストの外部送信(コンプライアンス) | Azure/ElevenLabs のデータ利用規約確認。機微が懸念なら経路Bで**アライメントはローカル**に留める。台本のみ送信、原ドラフトは送らない |
| ネットワーク障害・API 変更 | 合成結果 WAV をキャッシュ。VOICEVOX(プラン01)へフォールバック可能 |
| 日本語アクセントの不自然さ(特に ElevenLabs) | SSML/発音辞書で補正、看板回のみ採用 |
| タイムスタンプ精度(Google 等) | `--dtw` 強制アライメントで担保 |

---

## 6. 使い分け(→ README も参照)

- **既定はプラン01**(全10本の量産・完全無料/ローカル・同期最強)。
- **プラン02を選ぶのは**: ①声の自然さ・感情が視聴体験の要になる回、②2話者の掛け合いをより生っぽくしたい回、③外部送信が許容される前提。
- 両者は `timeline.json` という同一契約で接続されるため、**回ごと・話者ごとに TTS を混在**させることも可能(例: 講師=VOICEVOX、生徒=Azure、など)。映像テンプレ・レビュー体系・レンダは一切変えずに済む。
