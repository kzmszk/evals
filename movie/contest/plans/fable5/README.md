# fable5 設計プラン集 — 健康教育動画の生成システム

健康リテラシー教材ドラフト(Markdown)→ 二人の会話形式・音声つき解説動画(約5分・MP4)を、10本のドラフトに繰り返し適用できる形で生成するシステムの設計。

## プラン一覧

| プラン | 方式 | TTS | 同期の取り方 | 立ち位置 |
|---|---|---|---|---|
| [plan-01](plan-01.md) | **決定論的タイムライン** | VOICEVOX(ローカル) | **合成前**に mora 長から尺・語タイミングを計算(誤差ゼロ) | **既定/本命** |
| [plan-02](plan-02.md) | 自然音声優先 | クラウド Neural(Azure/ElevenLabs) | word-boundary イベント or 強制アライメント | 声の魅力を最優先する回向けの姉妹プラン |

## 共通の背骨

両プランは `draft.md → script.json → audio_query/tts → timeline.json → Remotion → MP4` という同一パイプラインを共有し、**`timeline.json` という同期データ契約で TTS と映像を疎結合**にしている。したがって:

- 映像テンプレート(Remotion)・人間レビュー体系・レンダ手順・再現性の仕組みは**両プラン共通**。
- 違いは **TTS モジュールと、そこから `timeline.json` を作る方法だけ**。
- プラン02は「プラン01の TTS を差し替えた変種」であり、独立の巨大システムではない。

## 使い分け指針

- **原則プラン01を採用**する。理由: 完全無料・完全ローカル・2話者を native に実現でき、何より「音声の尺を合成前に確定できる」ため同期がドリフトしない。10本量産の再現性・コストで最良。
- **プラン02に切り替える(または一部併用する)のは次の場合**:
  1. 声の自然さ・感情表現が視聴体験の決め手になる回(例: しみじみ語るテーマ、感情に訴えるフック)。
  2. 掛け合いをより生っぽくしたい看板回。
  3. 健康テキストの外部送信が許容される前提(懸念があれば、アライメントはローカルの `--dtw` に留める運用)。
- 両者は同一契約で接続されるため、**回ごと・話者ごとに TTS を混在**可能(例: 講師=VOICEVOX、生徒=Azure)。映像・レビュー・レンダは無改変。
