# 設計依頼書: 健康教育動画の生成システム

このドキュメントは、動画生成システムの設計コンテストで各モデル(fable5 / opus4.8 / gpt5.5)に共通で渡す設計依頼書である。あなた(設計者)はこの依頼書だけを前提に、独立して設計プランを作成すること。

## 作りたいもの

健康リテラシー教材のドラフト(Markdown)を入力とし、**音声つき解説動画(約5分)** を出力する動画生成システム。

### コンテンツのコンセプト

- 楽しく、気楽に、しっかり学べる
- シンプルなアニメーションと大きめの文字で、重要なワードやセンテンスを見せる
- 数十ページ(スライド/シーン)を切り替えながら約5分の動画にまとめる
- 音声シナリオはドラフトから自動生成し、AI ボイスで動画と連動させる
- 音声シナリオは **二人の会話形式**(掛け合いで学ぶスタイル)

### 入力となるドラフトの性質

`education/health/drafts/` に約80〜120行の Markdown が10本ある。構成は概ね「フック → クイズ → 正解 → 解説(エビデンス強度の注記つき)→ まとめ」。文体は軽妙な読み物調。タイトル例:

- 寝だめはできるか — 睡眠負債の返済計画
- 運動では(ほぼ)痩せない。それでも最強である理由
- 油の冤罪事件簿 — 40年間悪役だった脂質のほんとうの話
- お金で幸福は買えるか — 「年収◯◯万円で頭打ち」説の栄枯盛衰
- 脳トレより飲み会? — 認知症予防に本当に効くもの

システムは特定の1本専用ではなく、**この形式のドラフトならどれでも動画化できる**ことを目指す。

## システムへの要求

1. ドラフト → 会話形式の音声シナリオ → AI ボイス音声 → 映像(アニメーション+テキスト)→ 音声と映像の同期合成、という一連の流れを実現すること
2. **全自動である必要はない**。ところどころ人間が確認・修正・支援する工程を挟んでよいし、外部サービスを利用してもよい。ただし「どこを人間がやり、なぜそこなのか」を設計として明示すること
3. 完成した動画は MP4 等の一般的な形式で書き出せること
4. 1本作って終わりではなく、10本のドラフトに繰り返し適用することを想定した再現性を持つこと

## 制約

- 技術選定は自由。有料 API・無料 OSS・ローカルツール・外部 Web サービス、いずれも選択してよい。ただし**選定理由とコスト感(概算)を明記**すること
- 実行環境として以下の2台が利用可能。どちらか一方でも、役割分担して両方使ってもよい(使い分けるなら理由を明記):
  - **Windows 11 Pro マシン**: RTX 4090(VRAM 24GB)+ RAM 64GB — ローカル GPU 推論(TTS・画像/動画生成モデル等)が可能
  - **MacBook Pro**: M1 Pro + RAM 32GB
- 言語は日本語コンテンツ(音声も日本語)

## 成果物の形式

Markdown の設計ドキュメントとして提出する。**設計プランは1本でもよいし、アプローチが本質的に異なるなら複数本提出してもよい**(その場合は各プランを独立したドキュメントにし、使い分けの指針を添えること)。

各プランには少なくとも以下を含めること:

1. **アーキテクチャ概要** — パイプライン全体の構成図(テキストベースで可)とデータの流れ
2. **各工程の設計** — シナリオ生成 / 音声合成 / 映像生成 / 同期・合成のそれぞれについて、使う技術・ツールと処理内容
3. **音声と映像の同期方式** — 本システムの技術的な核。どうやってスライド切り替え・アニメーションを音声のタイミングに合わせるかを具体的に
4. **人間の関与ポイント** — どの工程で何を確認・修正するか、その理由
5. **技術選定の理由とコスト概算** — 動画1本あたり・初期構築それぞれ
6. **リスクと対策** — 品質面・技術面で予想される問題と回避策
7. **実装ロードマップ** — 最初の1本を完成させるまでの手順と概算工数

## 評価について

提出されたプランは別途定めた評価基準(実現可能性、同期設計の具体性、人間関与の設計、技術選定、コンテンツ品質への配慮、再現性・拡張性)に基づき採点される。美辞麗句より、実際に動くものを作れる具体性が評価される。
