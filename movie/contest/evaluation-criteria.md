# 評価基準: 動画生成システム設計コンテスト

fable5 / opus4.8 / gpt5.5 が独立に作成した設計プランを、fable5 が本基準に基づいて評価する。

## 評価の公平性について

- 評価者(fable5)は参加者でもあるため、評価時にはプランを **A / B / C と匿名化**して提示し、どのモデルの成果物かを伏せる
- 評価は本基準の観点ごとに採点し、根拠を引用つきで示すこと(印象点の禁止)
- 複数プランを提出したモデルは、**最高得点のプランをそのモデルの代表スコア**とする。ただし複数案の使い分け指針の質は「総合所見」で言及する

## 採点観点(100点満点)

### 1. 実現可能性 — 25点

そのまま着手して最初の1本が完成する見込みがあるか。

- 各工程が実在するツール・API で実際に実行可能か(存在しない機能・誇張された精度を前提にしていないか)
- 利用可能な実行環境(RTX 4090 搭載 Windows 11 機 / M1 Pro MacBook Pro)に整合しているか。GPU を使う選定なら VRAM 24GB に収まるか、環境の使い分けに無理がないか
- 工数見積りが現実的か(楽観の度合い)
- 「絵に描いた餅」度: 具体的なコマンド・データ形式・中間成果物まで踏み込んでいるか

### 2. 音声・映像同期の設計 — 20点

本システムの技術的な核心。配点を高くする。

- スライド切り替え・アニメーションを音声タイミングに合わせる方式が**具体的なメカニズムとして**説明されているか(タイムスタンプの取得方法、同期データの形式、合成時の適用方法)
- TTS の発話長が事前に確定しない問題(尺の揺れ)への対処があるか
- 会話形式(二人の話者交代)特有の間・テンポの扱いに言及があるか

### 3. 人間の関与ポイントの設計 — 15点

「全自動でなくてよい」という条件を設計に活かせているか。

- 人間が確認・修正すべき工程の選定が合理的か(品質リスクが高く自動化が難しい箇所に人間を置いているか)
- 確認作業のインターフェース(何を見て、何を直し、どう次工程に渡すか)が具体的か
- 逆に、自動化すべき箇所を不必要に手作業にしていないか

### 4. 技術選定とコスト — 15点

- 選定理由が要件(日本語 TTS 品質、会話形式、ローカル実行)に紐づいているか
- 代替案との比較・トレードオフの認識があるか
- コスト概算(動画1本あたり・初期構築)が明示され、妥当か

### 5. コンテンツ品質への配慮 — 15点

システム論に終始せず、出力される動画の質を設計しているか。

- ドラフトの持ち味(軽妙な文体、クイズ構成、エビデンス強度の注記)を動画にどう translate するかの構想があるか
- 「大きめの文字で重要ワードを見せる」「楽しく気楽に」というコンセプトが映像設計に反映されているか
- 5分・数十ページという尺の制約から逆算した情報量設計があるか

### 6. 再現性・拡張性 — 10点

- 10本のドラフトに繰り返し適用できる仕組みか(1本目専用のハードコードになっていないか)
- ドラフト形式の揺れ(章立て・分量の違い)への耐性
- 将来の改善(声の変更、テンプレート追加等)のしやすさ

## 評価手順

1. 全プランを匿名化(A/B/C…)して評価者に提示する
2. 評価者は観点ごとに採点し、**プラン本文からの引用を根拠として**スコアシートを作成する
3. 総合所見として、各プランの最大の強み・最大の弱点・「実際に採用するならどれか(またはどの組み合わせか)」を述べる
4. 結果は `movie/contest/results.md` にまとめる
